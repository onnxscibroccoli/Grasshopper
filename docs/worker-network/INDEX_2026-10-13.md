## Architecture and user objective

An Android Termux-first, optionally GitHub Actions-driven worker-network onboarding system for Oracle OCI, Google Cloud, Microsoft Azure, AWS, IBM Cloud, GitHub Actions, Cloudflare Workers and Render. User chooses providers and worker capabilities; software generates provider-specific steps, safely delegates browser OAuth/MFA and account eligibility review to the human, resumes state and later runs policy-approved self-hosted MCP jobs.

**Absolute constraint: no billable cloud usage and no billing upgrades.** Authentication alone is never authorization to spend. Do not automate account opening, acceptance of provider terms, card capture or converting free accounts to Pay-As-You-Go. A universal cross-cloud OAuth/password/card does not exist; use separate provider authorizations and, where supported, individually approved OIDC workload identity federation.

## Operator quickstart (after extracting the archive to a NEW, separate local directory)

```sh
cd /path/to/extracted/worker-network-kit
python3 -m unittest discover -s worker-network/tests -v
python3 worker-network/workerctl.py catalog
python3 worker-network/workerctl.py wizard
python3 worker-network/workerctl.py onboard --providers oci,gcp,github --output "$HOME/worker-onboarding-001.json"
python3 worker-network/workerctl.py status --file "$HOME/worker-onboarding-001.json"
python3 worker-network/workerctl.py handoff --provider azure
python3 worker-network/workerctl.py resume --file "$HOME/worker-onboarding-001.json"
```

Nothing installs packages, changes provider subscriptions, or creates VMs. `auth --provider X` must be invoked manually **on a private interactive phone/workstation terminal** with the official CLI installed. The code refuses OAuth invocation in CI. Do not share login codes, redirects, tokens, API keys or payment cards.
